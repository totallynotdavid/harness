# GitButler CLI embedding report

`but` is a standalone Tokio CLI, not a client of `but-server`. `crates/but/src/main.rs:1-4` calls `but::handle_args`; `crates/but/src/lib.rs:531-870` dispatches commands by creating a `Context` and invoking command handlers. `crates/but/Cargo.toml` has no Tauri or `but-server` dependency. `but-clap` is only a documentation generator around `but` (`crates/but-clap/src/main.rs:17-33`). The default legacy build does include `gitbutler-watcher`, but the watcher is started by `but tui` (`crates/but/src/command/legacy/status/tui/mod.rs:367-392`) or by `but-server` (`crates/but-server/src/projects.rs:50-108`), not by ordinary stacking commands.

`setup::init_ctx` discovers a non-bare Git repository and, in default legacy mode, looks up a registered project; if it is absent or incomplete, it prompts or errors with “run `but setup`” (`crates/but/src/setup.rs:102-250`). `but setup` adds the repository to the global project registry and configures the workspace/target (`crates/but/src/command/legacy/setup.rs:218-300`). Context storage defaults to `.git/gitbutler` (`crates/but-ctx/src/lib.rs:84-101`; `crates/but-project-handle/src/storage_path.rs:21-38`), and the project `but.sqlite` is lazily created and migrated on first DB access (`crates/but-ctx/src/lib.rs:1083-1086`; `crates/but-db/src/handle.rs:31-84`). Legacy discovery also reads global `<app-data>/projects.json` (`crates/gitbutler-project/src/storage.rs:8,119-151`). No server or daemon is required.

The binary directly lists 39 GitButler workspace crates in `crates/but/Cargo.toml` (13 optional legacy crates enabled by default), including graph/rebase/context/workspace/API/DB, forge/secret/settings, legacy project code, and the watcher. It also carries TUI-oriented dependencies (`ratatui`, `crossterm`, `arboard`, `syntect`, `minus`). This is much broader than Git plumbing, but it is not the Tauri or HTTP server stack.

Headless use is documented: `but setup --init` is explicitly for CI/CD (`crates/but/src/args/mod.rs:592-621`); commits accept `-m`/`--no-message` to avoid the editor (`crates/but/src/args/commit.rs:18-20`); `--json` and `BUT_OUTPUT_FORMAT=json` support tool output (`crates/but/src/args/mod.rs:55-83`); and the bundled reference documents scripted commit calls (`crates/but/skill/references/reference.md:181-207`). Tests invoke the binary through `env.but(...)` (`crates/but/tests/but/utils.rs:151-173`). `NO_BG_TASKS=1` disables optional background sync (`crates/but/src/setup.rs:268-281`).

## Verdict: conditional yes

Captain can add one `but` executable and use it for local stacking without a daemon, GUI, or forge account, provided each repository is bootstrapped/configured (usually `but setup`) and calls avoid prompts. It is not a stateless `gh`-style dependency: first use needs GitButler’s global registry plus per-repository metadata/database, and push/PR/refresh operations add remote credentials/auth requirements.

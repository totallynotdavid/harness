# North

## Promise

One operator runs a crew of agents across multiple projects from one place. The operator
spends attention on decisions that need human judgment.

## Boundaries

- Captain is a repository and CLI. It is not a harness, application, service, or
  general-purpose workflow framework.
- Project code stays in project repositories. This repo stores work about that code.
- Repeated, deterministic checks belong in scripts. Infrequent judgment belongs in a
  focused model pass.
- A reusable lesson belongs in a skill only when it crosses task boundaries. Otherwise it
  belongs in a note.

## Principles

- Choose the crew model explicitly. Never inherit it accidentally.
- Keep the always-loaded instructions small. Follow pointers when a workflow needs them.
- End every workflow step with a checkable criterion.
- Treat a review miss as a gate problem as well as a code problem.
- Merging and discarding are captain decisions.

## Signals

- A new session can orient from `map.md` and `cap reconcile`.
- Review findings decrease as gates improve.
- `paper-cuts.md` gets shorter over time.
- Always-loaded instructions stay small as capability grows.
